# 苍穹外卖 AI 主导开发计划

## Summary

目标是在 `F:\Java_Learning` 下从零完成一个“苍穹外卖”风格项目，周期按 **8 个工作日** 执行，交付一个可运行、可演示、可写进简历的版本。

默认技术栈：

- 后端：Java 17、Spring Boot 3、MyBatis、MySQL 8、Redis、JWT、WebSocket、Spring Task、Apache POI、Knife4j
- 管理端：Vue 3、Vite、Element Plus、ECharts
- 用户端：微信小程序；若本机没有微信开发者工具，则同步提供 H5 用户端用于演示
- 项目目录：`F:\Java_Learning\SkyTakeout\sky-take-out-ai`
- 开发方式：AI 生成代码，人负责验收、运行、排错确认、理解核心设计

## 执行纪律

- 所有项目文件必须放在 `F:\Java_Learning\SkyTakeout\sky-take-out-ai` 下，不得在 `F:\Java_Learning` 根目录直接创建同级项目目录。
- 必须严格按计划的“第 0 步、第 1 天、...、第 8 天”顺序一步一步执行；每一步开始前说明本步要做什么，完成后说明做了什么、验证结果是什么。
- 不得跨多个天数混合实现；进入下一天任务前，必须先完成当前天的验收项、测试项和当天 Git commit。
- 如果某一步验证失败，先说明失败原因和修复计划，修复并重新验证后再继续。
- 完成每天的任务后，必须在 `SkyTakeout/docs` 中按天数生成当天任务的详细记录 Markdown 文档，例如 `day-00.md`、`day-01.md`；文档要面向 0 基础读者，说明当天做了什么任务、代码结构如何、每个项目中的每个文件负责什么、执行了哪些验证、遇到什么问题以及如何解决。
- 每天的当天任务文档必须包含“手动验收方式及标准”章节，写清楚人应该如何启动项目、访问哪些页面或接口、执行哪些命令、看到什么结果才算当天目标完成。
- `SkyTakeout/docs/project-structure-and-capabilities.md` 是项目结构与能力总览文档，必须和每天的任务文档一起同步更新；每天结束时要更新当前目录结构、已完成能力、关键接口、运行方式、仍未完成能力。
- 每天结束必须提交一次 Git commit，提交信息按模块写，例如 `feat: add employee auth`；提交前必须确认测试/构建结果和 `git status`。

## Implementation Plan

### 第 0 步：准备与约束锁定，0.5 天

- 新建 Git 分支：`codex/sky-take-out-ai`
- 新建项目目录：`F:\Java_Learning\SkyTakeout\sky-take-out-ai`
- 初始化三个子项目：
  - `sky-server`：Spring Boot 后端
  - `sky-admin-web`：管理端 Vue
  - `sky-user-miniapp`：微信小程序端
- 配置本地依赖：
  - MySQL 数据库：`sky_take_out`
  - Redis：默认 `localhost:6379`
  - 后端端口：`8080`
  - 管理端端口：`5173`
  - 用户 H5 备用端口：`5174`
- 每天结束提交一次 Git commit，提交信息按模块写，例如 `feat: add employee auth`

### 第 1 天：后端骨架、数据库、公共能力

交付目标：后端能启动，数据库连通，接口文档可访问。

实现内容：

- 搭建 Spring Boot 多模块或清晰分包结构：
  - `common`：统一返回、异常、常量、JWT、上下文、分页
  - `pojo`：Entity、DTO、VO
  - `server`：Controller、Service、Mapper、Config
- 建表并导入基础数据：
  - `employee`
  - `category`
  - `dish`
  - `dish_flavor`
  - `setmeal`
  - `setmeal_dish`
  - `user`
  - `address_book`
  - `shopping_cart`
  - `orders`
  - `order_detail`
- 接入 Knife4j，访问路径默认为 `http://localhost:8080/doc.html`
- 建立统一接口返回格式：
  - 成功：`{ code: 1, msg: null, data: ... }`
  - 失败：`{ code: 0, msg: "错误信息", data: null }`
- 建立全局异常处理、参数校验、分页返回结构

验收：

- `sky-server` 启动无报错
- Knife4j 能打开
- MySQL 表结构完整
- `/admin/employee/login` 可在接口文档中看到

### 第 2 天：管理端登录、员工、分类

交付目标：管理端基础权限和 CRUD 跑通。

实现内容：

- 后端实现：
  - 员工登录
  - JWT 签发
  - JWT 拦截器
  - 当前登录用户上下文
  - 员工分页、新增、修改、启禁用
  - 分类新增、分页、修改、启禁用、删除
  - MyBatis 公共字段自动填充：`createTime`、`updateTime`、`createUser`、`updateUser`
- 管理端实现：
  - 登录页
  - Layout
  - 员工管理页
  - 分类管理页
  - Axios Token 自动附带
  - 登录过期跳转

验收：

- 未登录访问管理接口返回 401 或统一失败响应
- 登录后能进入管理端
- 员工和分类可以增删改查
- 分页、启禁用状态正确

### 第 3 天：菜品、套餐、文件上传

交付目标：商品基础数据管理完整可用。

实现内容：

- 管理端实现：

  - 套餐管理页
  - 图片上传组件
  - 菜品口味编辑

### 第 4 天：用户端登录、浏览、购物车、地址簿

### 第 5 天：下单、支付模拟、订单管理

## Public Interfaces And Data Contracts

### 管理端接口前缀

- `/admin/employee`
- `/admin/category`
- `/admin/dish`
- `/admin/setmeal`
- `/admin/order`
- `/admin/report`
- `/admin/workspace`
- `/admin/shop`
- `/admin/common/upload`

### 用户端接口前缀

- `/user/user`
- `/user/shop`
- `/user/category`
- `/user/dish`
- `/user/setmeal`
- `/user/addressBook`
- `/user/shoppingCart`
- `/user/order`

### 认证规则

- 管理端登录返回 `token`
- 用户端登录返回 `token`
- 除登录和静态资源外，所有业务接口必须携带 `Authorization: Bearer <token>`
- 后端从 Token 中解析当前用户或员工 ID，并写入请求上下文

### 核心数据规则

- 金额使用 `BigDecimal`
- 删除默认采用物理删除；订单数据不删除
- 菜品和套餐只有启售状态才在用户端展示
- 订单状态只能按允许路径流转：
  - 待付款 -> 待接单
  - 待付款 -> 已取消
  - 待接单 -> 已接单
  - 待接单 -> 已取消
  - 已接单 -> 派送中
  - 派送中 -> 已完成
